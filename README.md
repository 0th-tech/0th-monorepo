# 0th - Noir circuit proving a Google JWT for login

Testing the feasibility of a Starknet smart account gated on chain by a Google login, with a Noir proof.

1. The client generates a session key and logs in with Google. A hash of the key goes in the JWT's nonce.
2. A Noir circuit checks that Google signed this JWT and that its nonce matches the session key. `bb`
   turns that into an UltraHonk proof that keeps the JWT private.
3. The account's `register_session` checks the proof with a verifier generated by garaga, and Google's
   RSA key against a key registry, then accepts the session key as a signer until it expires.

## Setup

This project uses [asdf](https://asdf-vm.com) to manage versions, see [.tool-versions](.tool-versions).
Once asdf is installed, run `make tools`.

## Usage

```sh
make fixtures   # rebuild the test JWT and circuit inputs, only if you change them
make verifier   # prove the fixture, then regenerate the garaga verifier and its proof calldata
make test       # circuit tests (nargo) and contract tests (snforge)
make gas        # gas report of register_session with the real proof
make clean      # build outputs; make fclean also removes .venv and node_modules
```

## What a login costs

`make gas` on 2026-11-24 (snforge 0.64.1, scarb 2.18.0, garaga 1.1.0, the fixture's proof):

| Call | L2 gas |
|---|---|
| `register_session` | 167.0M |
| └ the verifier | 161.4M |
| └ the registry's `is_key` (a mock) | 0.2M |

- On Sepolia (2026-11-14), a login on an already deployed account cost 189.0M L2 gas, 4.98 STRK, about
  $0.16 at STRK $0.0327 (`0x626aafdd36c054f2741369905fbde81c9555e470179f0ea7f983e2ab31ae568`). On top of
  `register_session`, the transaction pays for its 3,092 calldata felts, the sending account's
  validation and the fee transfer.
- A smaller circuit would not help much: each doubling of its size only adds one sumcheck round and one
  point to the verifier's 58-point MSM.

## Conclusion

The logic works, but $0.16 per login is too expensive.
